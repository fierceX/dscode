# 注入冷却与信念度感知 — 设计文档

> 2026-05-20

---

## 一、背景与问题

### 1.1 当前注入机制的问题

在 `turn.rs::execute()` 的 Phase 4（stop="tool_use"），每次工具循环都调用 `DecisionEngine.decide()`。如果信念度持续低于阈值（B<0.70），每次工具循环都会注入新的提示词，导致：

| 问题 | 后果 |
|------|------|
| **重复注入膨胀上下文** | 同一轮内注入 3-5 条相同意图的消息，徒增 token 开销 |
| **模型脱敏** | 每次工具调用后都看到注入消息，模型逐渐忽略它们 |
| **没有冷静期** | 错误已修复后，信念度还没滑出窗口，仍被注入 |

### 1.2 缺少模型侧感知

当前注入消息是纯"事后通知"——模型只有在注入发生后才知道存在信念机制。系统提示词中对此完全沉默。

---

## 二、冷却机制 — 实现方案

### 2.1 核心思想

注入后的一段**冷静期**，在冷静期内即使信念度低于阈值也不再次注入。冷却由 `DecisionEngine` 内部管理，调用方无感知。

### 2.2 实现位置

冷却逻辑完全封装在 `DecisionEngine` 内部：

```rust
// DecisionEngine 自身持有 cooldown_remaining 字段
pub struct DecisionEngine {
    cooldown_remaining: usize,   // <-- 内部管理，外部不可见
    // ...
}

// 调用方只需传 belief 和 errors
pub fn decide(&mut self, belief: f64, errors: &[String]) -> Decision
```

TurnExecutor 持有一个持久化的 `DecisionEngine` 实例，而非每次创建新的临时对象。

### 2.3 工作流程

```
engine.decide(belief, errors) 被调用
  ├── B < 0.30 → Abort（强制清除冷却，中止本轮）
  │
  ├── cooldown_remaining > 0
  │   └── cooldown_remaining -= 1, 返回 None（跳过注入）
  │
  ├── B < 0.50 → Inject(Warning) + cooldown = 3
  ├── B < 0.70 → Inject(Reminder) + cooldown = 3
  └── else     → None
```

### 2.4 冷却参数

| 参数 | 默认值 | 含义 |
|------|:------:|------|
| `DEFAULT_COOLDOWN_TURNS` | 3 | 注入后跳过的 `decide()` 调用次数 |
| Abort 绕过冷却 | true | B<0.30 时始终中止，不等冷却 |

### 2.5 生命周期

| 事件 | 行为 |
|------|------|
| 新用户输入 | `engine.reset()` 清零（TurnExecutor.execute() 入口调用） |
| Abort 触发 | 内部清零（确保后续新轮从干净状态开始） |
| Inject 发生 | 设为 `DEFAULT_COOLDOWN_TURNS`（即 3） |

### 2.6 恢复验证

单次严重错误（severity=0.9）需约 2 次 clean call 恢复至 B=0.70，冷却期 3 次比恢复多 1 拍，确保信念真正稳定后才允许再次注入。

## 三、系统提示词信念度感知

### 3.1 实现方式

在 `prompt.rs::build_system_prompt()` 的 `<verification-gate>` 之后、`<stop-triggers>` 之前，添加 `<belief-awareness>` 区块。

### 3.2 内容（纯英文）

```
<belief-awareness>
This agent has a belief tracking system that monitors tool execution quality.
- Each tool call is evaluated for errors (compile failures, test failures, edit loops)
- A "belief score" (0.0–1.0) reflects recent tool execution reliability
- When belief drops below 0.70, a [System note] may be injected with recent errors
- When belief drops below 0.30, the task may be aborted

When you see [System note: ...] injected after your tool results:
1. Stop and review what went wrong
2. Use Read/Grep/Bash to verify state before making changes
3. Make smaller, more deliberate edits
4. Verify each fix before moving on
</belief-awareness>
```

**不需本地化**：统一使用英文。

## 四、信念度实时展示

### 4.1 TUI 状态栏

```
flash B:0.73 T:12 R:45 I:200K(50%) O:20K C:400K(40%) ¥0.12
```

- `B:0.73`：当前信念度（0.0~1.0），0.0 表示未追踪
- 每次工具调用后实时更新

### 4.2 终端标题栏

非 TUI 模式下，通过 ANSI escape `\x1b]0;...\x07` 将信念度写入终端标题栏。

### 4.3 更新时机

1. **每次工具调用后** — `BeliefTracker.observe()` 执行后立即更新
2. **Phase 4 决策前** — 标题栏显示最新信念度
3. **本轮结束后** — 最终信念度持久显示

## 五、影响范围

### 5.1 修改的文件（最终实现）

| 文件 | 修改类型 | 修改内容 |
|------|---------|---------|
| `src/agent/decision.rs` | 🔧 修改 | `decide()` 改为 `&mut self`，内部管理冷却计数器；新增 `reset()`、`cooldown_remaining()` |
| `src/agent/turn.rs` | 🔧 修改 | 持持久化 `decision_engine` 字段；Phase 4 直接调用 `engine.decide(belief, errors)` |
| `src/prompt.rs` | 🔧 修改 | 新增 `<belief-awareness>` 区块（纯英文） |
| `src/test_mock.rs` | 🔧 修改 | 更新所有 `decide()` 调用处（去掉第 3 参数） |

### 5.2 接口变化（最终）

```rust
// 旧
pub fn decide(&self, belief: f64, errors: &[String]) -> Decision

// 新 — 冷却由引擎内部管理
pub fn decide(&mut self, belief: f64, errors: &[String]) -> Decision
pub fn reset(&mut self)
pub fn cooldown_remaining(&self) -> usize
```

`TurnExecutor` 替换字段：

```rust
// 删除
cooldown_remaining: usize,

// 新增
decision_engine: DecisionEngine,
```

## 六、未解决的问题 / 后续改进

- **冷却参数可配置化**：当前硬编码，后续可在 `.dscoderc` 或 `Config` 中配置
- **自适应冷却**：信念度越低，冷却越长（如 B<0.40 时冷却 5 次，B<0.55 时冷却 3 次）
- **注入限频**：除冷却外，再加跨轮限频（如每 5 轮最多注入 1 次）
- **注入累积**：冷却期内收集的错误可在恢复后合并注入
- **信念度颜色**：TUI 目前信念度仅显示数值，未做颜色区分
